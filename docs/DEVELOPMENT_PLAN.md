## 1. 목표

핀-튜브 열교환기의 **CFD 케이스를 사람 손 없이 생성·실행·수확하는 앱**.

설계변수를 넣으면 → 형상 → 메시 → 경계조건 → 해석 → 결과 CSV 까지
GUI 조작 없이 커맨드로 완주하는 것이 최종 상태임.

### 목표가 아닌 것

| 아님 | 이유 |
|---|---|
| 범용 CFD 자동화 도구 | 형상·물리가 무한히 변하면 자동화가 반드시 깨짐 |
| 1D 성능 예측 도구 | HX-Sim 이 이미 담당. 중복 구현하면 반드시 갈라짐 |
| j/f 상관식 라이브러리 | 동일. 상관식은 HX-Sim 을 호출해 받아옴 |
| 최적화 엔진 | 배치 러너가 안정화된 뒤 논의 |

### 정형화가 성립하는 근거 — 불변량 3개

| 불변량 | 내용 | 자동화에 주는 것 |
|---|---|---|
| 위상 | 박스 + 실린더 배열 + 반토러스. 바디 클래스와 인접 관계 고정 | 존 매핑 테이블 하드코딩 가능 |
| 물리 | 단상 공기(포러스) + 관벽 conjugate + 관내 냉매 | 솔버 설정에 분기 없음 |
| 메시 위상 | 코어·직관은 스윕 가능, 벤드만 비정형 | 사이징을 파라미터의 함수로 유도 |

세 번째가 핵심임. 범용 툴에서 사람이 케이스마다 손으로 맞추는 게 메시 사이징인데,
여기서는 식으로 쓸 수 있음:

```
h_air  = (Pt - Do) / N_gap          기본값 (25.4-9.52)/10 = 1.59 mm
h_ref  = Di / N_d                   기본값 8.22/12        = 0.69 mm
h_bend = min(h_ref, πR / N_arc)
```

정수 세 개(`N_gap`, `N_d`, `N_arc`)만 앱이 갖고 있으면 어떤 파라미터 조합에도
사이징이 자동으로 나옴. **사람이 만질 값이 없음.**

## 3. 핵심 설계 결정

| 결정 | 내용 | 근거 |
|---|---|---|
| **핀은 형상 생성 안 함** | 코어를 포러스로, 블로키지는 γ로 | 핀 275장 실형상 = ~1×10⁹ 셀 |
| **관 내부는 실형상 해상** | 근사 없음 | 관벽 온도분포(conjugate)와 벤드 입구 재발달이 값어치 |
| **단상 우선** | 2상은 후순위 | 2상은 분배가 quality 지배 → 별도 접근 필요 |
| **다중 입출구는 플레넘으로** | 총유량 1개만 경계조건 | 회로별 유량을 사람이 가정하는 모순 제거 |
| **STEP (B-rep)** | STL 은 미리보기 전용 | 삼각형 근사는 곡률 사이징·경계층 파괴 |
| **면 이름은 좌표로** | `face_seeds` 최근접 매칭 | STEP 은 바디 이름만 싣고 면 이름은 못 실음 |
| **j/f 는 HX-Sim 호출** | 자체 구현 안 함 | 두 곳에 두면 반드시 갈라짐 |
| **검증된 봉투 강제** | `envelope.yaml` 밖은 실행 거부 | "정형화된 툴"과 "조용히 틀리는 툴"의 경계 |

### 포러스는 근사가 아니라 멀티스케일 분해

| 방식 | 도메인 | 셀 수(개략) | 역할 |
|---|---|---|---|
| A. 풀사이즈 + 핀 실형상 | 88×317.5×500 | ~1×10⁹ | 비현실적 |
| **B. 풀사이즈 + 포러스** | 동일 | ~16×10⁶ | **주력** |
| **C. 축소 조립 + 핀 실형상** | 4열×3단×20mm | ~22×10⁶ | **B 의 폐합 검증** |
| **D. 주기 단위셀** | 1핀피치 × 1관피치 | ~1.2×10⁶ | **j/f 추출** |

A 는 B 의 약 64배인데, 핀 사이 유동은 국소 주기적이라 275개 통로가 사실상 같은 답을
반복함. D → B 로 j/f 를 넘기는 구조가 맞고, **C 를 반드시 지원해야** B 를 검증할 수단이 생김.

**포러스가 못 잡는 것**: 핀 표면 국소 온도장, 착상/응축수 거동, 루버 각도 변경의 직접
효과 → D 로 감. **잘 잡는 것**: 전면 속도 분포, 코일 내부 재분배, 열별 성능 편차.

## 4. 파이프라인 — 단계별 산출물 계약

```
case.json ─▶ [GEOM] ─▶ .step ─▶ [MESH] ─▶ .msh.h5 ─▶ [LABEL] ─▶ zones.json
                                                                    │
        results.csv ◀─ [POST] ◀─ .dat.h5 ◀─ [SOLVE] ◀─ .cas.h5 ◀─ [SETUP]
```

| 단계 | 입력 | 산출물 | 소요 |
|---|---|---|---|
| `geom` | case.json | .step + manifest.json | 초 |
| `mesh` | .step | .msh.h5 + 품질 리포트 | 분 |
| `label` | .msh.h5 + face_seeds | zones.json | 초 |
| `setup` | 위 전부 | .cas.h5 | 초 |
| `solve` | .cas.h5 | .dat.h5 + 수렴 이력 | 시간 |
| `post` | .dat.h5 | results.csv + 필드 | 분 |

```bash
fthx-run case.json --to mesh           # 메시까지만
fthx-run case.json --to setup          # 셋업된 cas 만 (GUI 로 열어 확인)
fthx-run case.json --from solve        # 메시 재사용
fthx-run case.json --to post --resume  # 바뀐 단계부터만
fthx-run sweep.yaml --jobs 4           # 배치
```

**해시 기반 캐싱** — 입력 JSON + 단계 파라미터를 해시해 산출물에 박음. 물성만 바꾸면
geom/mesh 를 건너뛰고 setup 부터 돎. 메시 30분 걸린 걸 BC 오타로 날리지 않는 게 배치의 전제.

**`label` 을 별도 단계로 분리한 이유** — 가장 조용히 틀리는 지점임. 매칭 결과를 파일로
남겨 사람이 확인할 수 있어야 하고, 최근접 거리가 임계값을 넘으면 즉시 실패시켜야 함.

## 5. 모드 체계

### 열 모델 (SETUP 단계만 영향, GEOM·MESH 불변)

| 모드 | 내용 | 용도 |
|---|---|---|
| `none` | 단열, 압력강하만 | 팬 매칭·유동 분포 스크리닝. 최속 |
| `equilibrium` | 단일 온도 포러스 + UA 소스항 | **안전한 기본값**. 핀효율을 직접 입력 |
| `netm` | 2온도 (유체상/고체상), a_v·h·k_eff | 핀효율이 해에서 나옴. 접합 정의 까다로움 |

### 도메인 모드

| 모드 | 대응 | 용도 |
|---|---|---|
| `full_porous` | B | 주력 |
| `reduced_resolved` | C | 폐합 검증 |
| `periodic_cell` | D | j/f 추출 → closure/on_design |

### 3-mode 규약 (기존 컴포넌트 시뮬레이터와 일치)

- Off-design = 실험 j/f 데이터
- Semi-empirical = 상관식 (HX-Sim 호출)
- On-design = periodic_cell CFD 결과

**확정**
- 존 이름: `{바디}-solid` / `{바디}-solid:1` / `{A}-solid-{B}-solid` / `interior--{바디}-solid`
- Share Topology·imprint·벤드 메싱 전부 동작

**발견 3건 (전부 설계에 반영됨)**
1. **계면 존 이름을 신뢰할 수 없음** — 관벽↔코어/냉매는 별도 이름 없이 이웃 존에

2. **Proximity cells-per-gap 이 셀 수를 지배** — 기본 3 이면 관벽(0.65mm)을
   틈새로 보고 t/3 까지 자동 세분화. 1.31M → 68.6k (19배)
3. **관벽이 품질 병목** (0.225) — poly 가 얇은 환형에 눌림 → Thin Volume Mesh

**NETM 열수지 검증은 M3 로 이월** (SETUP 단계에서 확인)

### C — 완료 (메시 전략 + 셀 추정)

- **사이징 유도**: `h_air=(Pt−Do)/N_gap`, `h_ref=Di/N_d`,
  `h_bend=min(h_ref, πR/N_arc)`, **`cells_per_gap`**
- **경계층 불필요**: y+ = 190(4회로) / 131(6회로) 로 이미 벽함수 범위.
  프리즘 5층은 냉매를 2.8M→7M+ 로 늘리기만 함. 저유량 시 완충층 진입을 감시
- **관벽**: Bi≈6e-4 → 두께 방향 등온 → Thin Volume Mesh 1층
- **실측 보정 추정기**: `cells = K·V/h³`. K 는 M0 두 케이스에서 역산.
  관 관련 존 ±1%, core ±17%, 상·하류 ±40%.
  실측 2건이 추정 범위 안에 들어옴(−7.5% / +8.7%)
- **전체 케이스 13.9~17.1 M** — 상·하류 연장이 27~40% 를 차지

## 7. 무인 운전 — 게이트와 사다리

자동화의 난이도는 "돌리기"가 아니라 **"실패를 스스로 알아채고 처리하기"** 에 있음.

### 메시 품질 게이트

| 지표 | 통과 | 실패 시 |
|---|---|---|
| max skewness | < 0.90 | 사다리 1단 |
| min orthogonal quality | > 0.10 | 사다리 1단 |
| 셀 수 | < 상한 | 즉시 중단 |
| **존 수 = STEP 바디 수** | 일치 | **즉시 중단** (임포트 실패 신호) |

**메시 재시도 사다리**: 기본 사이징 → 국부 세분화 → 기준 크기 ×0.8 → 벤드 별도 사이징 → 실패 기록 후 다음 케이스

### 수렴 판정

residual 만 보면 안 됨. 물리량 감시 필수:
공기측 ΔP, 총 전열량 Q, **회로별 질량유량** 의 이동평균 기울기가 N회 연속 임계값 이하.

**발산 대응 사다리**: URF 하향 → 1차 상류 → pseudo-transient 시간스텝 축소

### 이력 보존

케이스마다 입력 해시·메시 통계·수렴 이력·게이트 통과 여부를 함께 저장.
200케이스 배치에서 이게 없으면 어느 결과를 믿을지 판단 불가.

## 9. 알려진 지뢰

| 항목 | 내용 |
|---|---|
| **Superficial vs Physical Velocity** | 포러스 존 체크박스. 틀리면 ΔP 가 1/γ² 배 어긋남. **압도적 1위 오류원** |
| **Share Topology = All** | 안 켜면 포러스↔관벽이 conformal 로 안 붙음 → conjugate 성립 안 함 |
| **porous jump 는 interior 필요** | 피더를 두 바디로 쪼갠 이유. conformal 실패 시 jump 걸 데가 없어짐 |
| **NETM k_eff 이방성** | 등방 k 를 넣으면 핀효율 과대평가 |
| **PyFluent 버전 의존** | `ansys-fluent-core` 를 Fluent 릴리스에 핀 고정 + CI 잠금 |
| **셀 수** | 공기 13.9M + 냉매 2.5M ≈ 16M. 배치 시 축방향 스윕으로 축소 검토 |
